# API 안정성

pylopdf는 [시맨틱 버저닝](https://semver.org/)을 따릅니다.

## v1.0 이전 { #current-status }

pylopdf는 1.0 이전 단계입니다. 0.16에서 [로드맵](https://github.com/yhay81/pylopdf/blob/main/ROADMAP.md)에 따라 한 API 재설계처럼 릴리스에는 여전히 호환되지 않는 변경이 포함될 수 있으며, 아직 사용 중단 기간도 없습니다. 모든 호환되지 않는 변경은 코드를 고치는 방법과 함께 [변경 이력](https://github.com/yhay81/pylopdf/blob/main/CHANGELOG.md)에 기록됩니다. 원하는 시점에 업그레이드하려면 마이너 버전을 고정하세요(예: `pylopdf~=0.16.0`).

아래 규칙은 v1.0부터 적용됩니다.

## 공개 API의 범위 { #public-api-boundary }

공개 API는 다음과 같습니다.

- `pylopdf.__all__`의 이름과 `pylopdf.__version__`
- 그 클래스들의 문서화된 메서드, 속성, 애트리뷰트
- 매개변수의 이름, 기본값, 위치 인수인지 키워드 전용인지 여부
- 문서화된 반환값, 상수, 열거형 값
- 반환되는 딕셔너리의 키와 반환되는 튜플의 필드
- 예외 클래스와 그 계층, `LimitError.code`

그 밖의 것은 모두 비공개입니다. `_`로 시작하는 이름, `pylopdf.pylopdf_core` 확장 모듈, `repr()` 출력, 오류 메시지의 문구, 경고의 순서, 문서화되지 않은 애트리뷰트가 여기에 해당합니다. 공개 이름은 정의된 모듈이 아니라 `pylopdf`에서 직접 import하세요.

저장한 PDF, PNG, SVG의 정확한 바이트는 릴리스마다 바뀔 수 있습니다. 안정적인 것은 그 겉모습, 구조, 그리고 거기서 추출되는 텍스트입니다.

## v1.0 이후 { #after-v1 }

- **메이저** 릴리스는 공개 API를 제거하거나 변경할 수 있습니다.
- **마이너** 릴리스는 기존 코드를 깨뜨리지 않고 기능을 추가합니다.
- **패치** 릴리스는 버그를 수정합니다.

공개된 것을 제거하거나 이름을 바꾸는 것, 필수 매개변수를 추가하는 것, 반환되는 레코드에서 필드를 제거하는 것, 이전보다 적은 입력을 받아들이는 것, 예외 계층을 바꾸는 것에는 메이저 릴리스가 필요합니다. 함수, 메서드, 선택 매개변수, 허용되는 값, 레코드 필드를 추가하는 것은 그렇지 않습니다. 타입 힌트도 API의 일부입니다. 매개변수나 레코드 필드의 타입을 바꾸는 것도 호환되지 않는 변경입니다.

## 사용 중단 { #deprecation-lifecycle }

v1.0 이후 제거될 API는 다음 절차를 거칩니다.

1. 대체 방법과 제거될 수 있는 가장 이른 릴리스와 함께 사용 중단으로 문서화합니다.
2. 가능한 경우 `DeprecationWarning`을 발생시킵니다.
3. 최소 두 번의 마이너 릴리스와 6개월 동안 유지합니다.
4. 메이저 릴리스에서만 제거합니다.

`PylopdfWarning`은 PDF 파일의 문제를 알리며 사용 중단에는 절대 사용하지 않습니다. 보안, 법률, 업스트림의 긴급 상황에서는 더 짧은 절차가 필요할 수 있으며, 그때는 변경 이력과 릴리스 노트에 분명히 밝힙니다.

## 결과의 변경 { #behavior-and-data }

이전 결과가 잘못되었다면 버그 수정으로 결과가 바뀔 수 있습니다. 예를 들어 읽기 순서, 표 감지, 글리프 위치, 색상, 손상된 파일의 복구 방식 등입니다. 이런 변경은 어떤 릴리스에서도 나올 수 있으며, 주목할 만한 것은 변경 이력에 기록됩니다.

새 리소스 제한이 이전 릴리스에서 처리하려 했던 악의적이거나 예상외로 비용이 큰 파일을 거부할 수 있습니다. 프로그램은 메시지 문구가 아니라 예외 타입과 `LimitError.code`에 의존해야 합니다.

지원하는 Python 버전과 플랫폼은 릴리스마다 명시합니다. 업스트림에서 수명이 끝난 Python 버전의 지원은 마이너 릴리스에서 중단될 수 있으며, 릴리스 노트에 이를 밝힙니다.

## 변경 추적 방법 { #compatibility-review }

저장소는 공개 API를 [`api/public-api.json`](https://github.com/yhay81/pylopdf/blob/main/api/public-api.json)에 기록하며, 기록을 갱신하지 않은 채 API가 바뀌면 테스트가 실패합니다. 따라서 공개 API의 모든 변경은 의도적으로 검토됩니다.
